# 机器人售后排障与备件智能调度智能体——详细需求文档

## 一、文档概述

| 项目 | 内容 |
|---|---|
| 项目名称 | 机器人售后排障与备件智能调度中枢（代号：Service Copilot） |
| 文档版本 | V1.0 需求规格说明书 |
| 目标场景 | 工业机械臂、仓储 AGV 等机器人集群运行维护、故障现场/自动报修、手册知识检索与备件库存跨系统调度 |
| 核心用户 | 一线售后/驻场工程师、车间操作员、售后主管、备件库管员 |

本智能体的定位是：在现有 ERP/WMS 业务系统与本地非结构化运维手册之上增加一个**智能调度与排障中枢层**。系统不推翻重构现有工业数据库，而是通过多智能体协同、RAG 语义检索与受控 Text2SQL 推理能力，将传统“人肉翻手册、手动查库存、线下批工单”的人工流转过程，升级为具备“双通道接入、自动语义理解、智能备件匹配、人在回路审批”的端到端自动化智能体工作流。

## 二、用户画像与核心场景

### 用户角色

**角色A：一线售后/驻场工程师（现场处置与排障）**
- **关注**：快速获取故障处置 SOP、精准定位所需备件型号与规格。
- **典型输入**："苏州厂3号车夹爪不动了，屏幕报错 E-201 且气缸有漏气声，怎么修？需要换什么件？"

**角色B：车间操作员（初级故障报修）**
- **关注**：非结构化报修输入、确认报修单状态与响应时效。
- **典型输入**："喷涂车间2号机械臂抖动严重停机，红灯长亮。"

**角色C：售后主管（运维风控与工单审批）**
- **关注**：高价值备件出库审批、疑难故障审核、全局排障效率闭环。
- **典型动作**：审核 Agent 提报的《E-201 故障排障与电磁阀出库申请工单》，点击“确认调拨”或“驳回重查”。

**角色D：备件库管员（仓储履约）**
- **关注**：接收包含明确仓位号、备件编码的调拨出库单，快速打包装箱发货。
- **典型动作**：依照系统推送的调拨通知，完成“苏州中心仓 A-03 货位”备件核销。

### 核心场景（按优先级排序）

**场景1：双通道故障接入与标准化解析（最高优先级）**
- **通道 A（人工口语化报修）**：针对保密隔离厂区或复杂机械异响，工程师通过自然语言输入故障，智能体提取设备 SN、故障代码、伴随现象与厂区位置。
- **通道 B（联网设备自动上报）**：联网机器人触发严重警报瞬间，通过 Webhook/MQTT 主动推送包含错误码与运行日志片段的结构化 JSON，系统跳过意图解析直接进入排障流水线。

**场景2：基于 RAG 的故障手册智能匹配与备件决策（核心优先级）**
智能体结合故障特征，从数百页原厂 PDF 维修手册切片中执行混合检索（关键词+语义向量），精准定位排障章节。若涉及损耗件，大模型自动从 SOP 文本中抽取目标备件的标准物料品名。

**场景3：受控 Text2SQL 备件库存实时透视（核心优先级）**
识别出更换备件后，智能体利用带防护的 Text2SQL 引擎，穿透底层 ERP/WMS 数据库查询对应厂区就近仓库的实时库存、在途库存及货位信息。

**场景4：人在回路（HITL）工单流转与闭环下发（高优先级）**
对涉及备件更换或高风险停机的任务，智能体将工作流挂起（Suspend），自动整合“故障归因+维修建议+库存余量”生成工单草稿并推送到主管审批终端。主管审批通过后唤醒工作流，执行库存锁定并下发派工。

### 多智能体协作机制

系统基于 **LangGraph** 编排为带环有向图（State Graph），通过共享强类型的 `AgentState` 并在状态变更时驱动节点跳转：

1. **Router Agent（路由分发中枢）**：校验输入通道。针对通道 A 执行槽位抽取；针对通道 B 直接读取 JSON Payload；若核心参数完备，将控制权转交 `Diagnose_Agent`。
2. **Diagnose Agent（排障诊断智能体）**：挂载 Qdrant 检索工具。根据 `error_code` 和文本特征执行 RAG 召回，判定是否需更换备件并抽取标准品名。若需换件，触发转交 `Inventory_Agent`；若仅需调试，直接跳转至工单生成。
3. **Inventory Agent（库存调度智能体）**：通过安全的 Text2SQL 查询引擎，将提取的备件品名转化为参数化 SQL，查询本地 ERP 库存表，返回就近仓储与余量信息。
4. **HITL Coordinator（中断协同）**：汇集前序节点的诊断结论与库存状态，生成工单后触发 LangGraph `interrupt()` 挂起执行。由主管在 UI 审批后，唤醒流程并将终态入库。

### 关键技术选型建议

| 模块 | 建议方案 | 理由 |
|---|---|---|
| 工作流编排 | LangGraph + LangChain | 原生支持复杂多智能体条件分支、循环自我纠错与状态持久化中断（HITL） |
| API 接入网关 | FastAPI (Python 异步) | 高吞吐量处理机器 Webhook 上报，与主流 AI 框架生态天然融合 |
| 向量检索库 | Qdrant (本地 Docker 部署) | 资源占用极低、支持混合检索与高维过滤，高度契合私有化机房交付 |
| 关系型数据库 | MySQL 8.0 + SQLAlchemy | 存放企业 ERP 库存与工单核心业务数据，提供完备事务支持 |
| 安全数据查询 | SQLAlchemy 参数化绑定 | 彻底隔离并防止 Text2SQL 场景下的 SQL 注入与越权读写 |
| 状态与会话缓存 | Redis 7.0 | 用于 LangGraph Checkpointer，保证工单审批中断时状态跨节点不丢失 |
| 日志与链路追踪 | Loguru + Langfuse | Loguru 负责进程内 Trace ID 穿透，Langfuse 负责大模型 Token 与 Prompt 效能可观测性 |

### 核心调度与安全拦截逻辑（伪代码）

```python
from langgraph.graph import StateGraph, END
from sqlalchemy import text
from typing import TypedDict, Optional

class AgentState(TypedDict):
    device_sn: str
    error_code: str
    symptom: Optional[str]
    location: str
    need_replace: bool
    part_name: Optional[str]
    stock_info: Optional[dict]
    approval_status: Optional[str]

def inventory_sql_node(state: AgentState):
    """安全 Text2SQL 查询节点，参数化防注入"""
    part_name = state.get("part_name")
    location = state.get("location")
    
    # 模拟 LLM 决策出的查询语义，强制参数化注入
    query = text("""
        SELECT warehouse_name, stock_qty, bin_location 
        FROM spare_parts_inventory 
        WHERE part_name = :part_name AND region = :location AND stock_qty > 0
        ORDER BY priority ASC LIMIT 1
    """)
    
    with db_engine.connect() as conn:
        result = conn.execute(query, {"part_name": part_name, "location": location}).mappings().first()
        
    return {"stock_info": dict(result) if result else {"stock_qty": 0, "status": "OUT_OF_STOCK"}}

def build_workflow():
    workflow = StateGraph(AgentState)
    workflow.add_node("router", router_node)
    workflow.add_node("diagnose", diagnose_rag_node)
    workflow.add_node("inventory", inventory_sql_node)
    workflow.add_node("generate_order", generate_order_draft_node)
    
    # 编排条件边
    workflow.set_entry_point("router")
    workflow.add_edge("router", "diagnose")
    workflow.add_conditional_edges(
        "diagnose",
        lambda s: "inventory" if s["need_replace"] else "generate_order"
    )
    workflow.add_edge("inventory", "generate_order")
    # 设置工单生成后中断，进入 Human-in-the-loop 等待主管审批
    app = workflow.compile(checkpointer=redis_checkpointer, interrupt_before=["generate_order"])
    return app
```

## 五、非功能需求（NFR）

| 维度 | 要求 |
|---|---|
| **性能指标** | 通道 B Webhook 接收与校验 $\le 100\text{ ms}$；Qdrant 向量检索耗时 $\le 500\text{ ms}$；端到端工单草稿生成 $\le 5\text{ s}$ |
| **系统可用性** | 调度智能体服务可用性 $\ge 99.5\%$；外部接口调用失败具备自动重试机制（指数退避，最多 3 次） |

## 六、实施路线图建议（MVP 三阶段）

### 阶段一：最小闭环与基础设施打桩（Week 1）
- 编写 `docker-compose.yml`，在本地环境一键拉起 MySQL、Redis、Qdrant 集群。
- 构建初始假数据源（Seed Data）：在 MySQL 录入 50 条多仓备件库存表；将一份包含真实故障（如 `E-201` 对应电磁阀）的排障 PDF 手册切片向量化导入 Qdrant。
- 搭建基础 FastAPI 骨架，完成通道 A 与通道 B 的输入数据格式校验。

### 阶段二：智能体工作流与安全攻坚（Week 2）
- 基于 LangGraph 编写核心有向图，串联 `Router`、`Diagnose`（RAG）与 `Inventory`（Text2SQL）节点。
- 实现防注入 Text2SQL 中间件改造，确保大模型生成的查询经由 SQLAlchemy `text()` 绑定安全执行。
- 接入 LangGraph Checkpoint（Redis），调试 `interrupt()` 中断逻辑，跑通“生成草稿 $\to$ 挂起 $\to$ 恢复派单”闭环。

### 阶段三：前端看板与端到端联动测试（Week 3）
- 基于 Streamlit 快速实现直观的 UI：左侧包含人工口语提问输入与一键模拟 Webhook 上报按钮；右侧展示推理全过程、手册依据、库存状态与主管审批弹窗。
- 编写自动化打桩测试脚本 `mock_robot_alert.py`，持续模拟高频告警压力。
- 输出系统全链路测试报告，将完整工程打包并梳理部署文档。

## 七、风险与缓解措施

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| **大模型生成恶意/越权 SQL** | 导致数据库表被清空或泄露敏感资产 | 强制实行“数据库最小只读权限 + 框架参数化绑定中间件”，双重物理阻断破坏行为 |
| **大模型出现排障幻觉与误配件** | 导致维修方向偏差或发错备件，延误抢修 | 引入强制原文引用机制；必须检索到置信度符合阈值的手册依据方可提取备件，并由主管审批把关 |
| **车间工业现场完全物理断网** | 云端公共大模型无法访问 | 方案预留内网 MCP 协议接入，并在本地支持加载 Ollama/vLLM 私有化量化小模型运行 |
| **复杂异响无标准故障代码** | RAG 检索命中率下降 | 路由节点检测到低置信度时，自动转向 `Clarify_Agent` 引导工程师输入标准化特征词 |

## 八、成功度量指标

| 指标 | 目标值 | 衡量方式 |
|---|---|---|
| **排障准备响应时长** | 从传统人工约 60 分钟下降至 $\le 2$ 分钟 | 从接收报修到生成经审批工单的端到端耗时对比 |
| **维修手册 SOP 召回准确率** | $\ge 95\%$ | 在已知真值的历史故障测试集（50+ 用例）上回归统计 |
